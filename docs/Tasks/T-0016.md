# T-0016: `pytest.ini` is inert, and the suite imports only by alphabetical luck

**Status:** [ ]
**Branch:** _not created_
**Created:** 2026-09-08
**Filed by:** T-0013

## Context

Two coupled defects in the test setup, found while running the suite to verify T-0013. The
suite is **green today** (486 passed, 1 skipped) — this is about it being green by accident.

### Defect A — `pytest.ini` uses the wrong section header

The file opens with `[tool:pytest]`, which is the header for `setup.cfg`. In a `pytest.ini`
the section must be `[pytest]`. Pytest reports `configfile: pytest.ini` — so the file is
found — but the section is never read, and every setting in it is silently discarded:

```
testpaths, python_files, python_classes, python_functions,
addopts (--verbose --tb=short --cov=src/latarnia --cov-report=html
         --cov-report=term-missing --asyncio-mode=auto),
markers (unit, integration, slow)
```

Proof: pytest's own header prints `asyncio: mode=Mode.STRICT` while the file asks for
`--asyncio-mode=auto`. Coverage never runs either, which makes the `--no-cov` flag in every
documented command a no-op.

### Defect B — `sys.path` depends on collection order

The package is not installed in the venv (no editable install, no `.pth`, no `conftest.py`),
so `import latarnia` works only because **12 test modules** each carry:

```python
sys.path.insert(0, str(Path(__file__).parent.parent.parent / "src"))
```

Modules without that line — `tests/unit/test_config.py`,
`tests/integration/test_auth_flow.py` and others — import successfully only when a sibling
that *does* have it was imported first. Since pytest collects alphabetically, the outcome
depends entirely on filenames:

| Command | Result | Why |
|---|---|---|
| `pytest tests/unit/` | 429 pass | `test_app_manager.py` sorts before `test_config.py` and inserts `src` |
| `pytest tests/unit/test_config.py` | collection error | run alone, nothing inserted `src` |
| `pytest tests/` | collection error | `integration/` collects first, and its alphabetically-first module `test_auth_flow.py` has no insert |
| `PYTHONPATH=src pytest tests/` | 486 pass | path supplied externally |

So the command `docs/SYSTEM.md` documented — `python3 -m pytest tests/ -v --tb=short
--no-cov` — has been broken as written. T-0013 corrected the documented command to include
`PYTHONPATH=src`; this task is the real fix. Renaming a test file could break the build
today.

## Scope (proposed — confirm before implementing)

- Fix the header to `[pytest]`, then **re-run and re-baseline**: this activates `addopts`
  for the first time, which turns on coverage (three report flags) and switches asyncio to
  auto mode. Expect output changes and possibly newly-failing async tests that currently
  pass under STRICT. This is the reason T-0013 did not fix it inline — it is a behaviour
  change, not a typo fix, and it should not ride along with a promotion.
- Add `pythonpath = src` to the corrected section (pytest ≥ 7 supports it), then delete the
  12 `sys.path.insert` lines. Alternatively add a single `tests/conftest.py`, or install the
  package editable — pick one and use it everywhere.
- Re-check whether `--cov` belongs in `addopts` at all: it has never actually run, so
  turning it on may surface a coverage gate nobody has seen.

Sequencing note: fix Defect B first and confirm the suite still passes with no
`PYTHONPATH`, then fix Defect A separately so the coverage/asyncio changes are isolated in
their own commit.

Promotion triggers to re-check when picked up: test configuration only — no subsystem, no
schema, no new service. Stays a Task.
