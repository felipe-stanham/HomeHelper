# T-0010: Dev-only TOTP bypass for browser test automation

**Created:** 2026-08-06 | **Status:** [DONE] | **Branch:** `task-T-0010-dev-totp-bypass`

## Problem

Browser-level test automation (Playwright MCP) cannot get past `/auth/login`. TOTP is the
only authentication method, so an automated run has no way to produce a valid 6-digit code
without out-of-band access to the user's encrypted TOTP secret.

Two separate obstacles, not one:

1. **The code itself.** `TOTPAuthProvider.validate` requires a code matching the RFC 6238
   window (`src/latarnia/auth/providers/totp.py:145-155`).
2. **Replay rejection.** Even with a correct code, `last_totp_window` must advance strictly
   (`totp.py:157-174`), so two logins inside the same 30 s window fail — the second logs
   `Rejected replayed TOTP code`. A per-test login would fail intermittently.

## Decision

Add an early-return bypass in `TOTPAuthProvider.validate` gated on **two independent
conditions**: the **raw** `ENV` variable is exactly `dev` **and** `LATARNIA_DEV_TOTP_BYPASS` is set truthy in `secrets.env`.
Placed after the 6-digit length check and before any DB access, so it also sidesteps
obstacle 2.

**Alternative considered and rejected by the operator:** seeding a session row directly via
`SessionStore.create_session` from a dev-only script, which would have required zero change
to production code. Rejected in favour of keeping the automation driving the real login UI
with no external tooling. Recorded here because it is the reason this task accepts a
bypass branch inside the platform's most security-critical function.

**Gating on ENV alone was explicitly rejected.** `MEMORY.md`
(`deploy-needs-host-config-json`) records a real incident where per-host config went missing
and the env root mis-resolved on a **prd** host. Config drift on these hosts is demonstrated,
not hypothetical, so a single-condition gate is not acceptable. The second condition is a
secret that exists in no `tst` or `prd` `secrets.env`.

## Tasks

- [x] `TOTPAuthProvider.__init__` accepts `dev_bypass: Optional[Callable[[], bool]] = None`.
      Default `None` means no bypass — the provider is safe by construction and the policy
      decision lives in `main.py`, not in the crypto module.
- [x] `validate()` early-returns `True` when `dev_bypass()` is truthy, after the 6-digit
      length check and before the credential lookup. Emit a WARNING naming the user each
      time, so a bypassed login is never silent in the log.
- [x] `main.py`: `_dev_totp_bypass_enabled()` returns `True` only when the **raw** `ENV`
      is exactly `dev` **and** `LATARNIA_DEV_TOTP_BYPASS` parses truthy. Check `ENV`
      **first** so `tst`/`prd` cost one string compare and never read `secrets.env` on
      the login path.
      **Amended after code review (BLOCK):** the gate must NOT delegate to
      `ConfigManager.get_env()`. That helper falls back to `"dev"` for anything outside
      `{dev,tst,prd}` and for an unset `ENV` (`core/config.py:170-171`), which made
      condition 1 **fail open** — `ENV="PRD "`, `ENV=production`, and a missing `ENV=`
      line all resolved to `"dev"` and would have satisfied the gate on a prd host,
      defeating the entire point of the two-condition design. Fixed by comparing
      `os.environ.get("ENV")` exactly against `"dev"`: no case folding, no strip, no
      default. Verified empirically across all of those values.
- [x] Wire it into the `TOTPAuthProvider` construction in `main.py`.
- [x] Startup checks, alongside the existing `LATARNIA_TOTP_ENC_KEY` / `LATARNIA_JWT_SECRET`
      loud-but-soft checks:
      - bypass active (`ENV=dev` + secret set) → WARNING banner stating authentication is
        disabled and that this must never be an env other than dev.
      - secret set while `ENV != "dev"` → **ERROR**, stating it is being ignored. This is the
        alarm for the exact config-drift failure mode that ruled out a single-condition gate.
- [x] Document the flag in `docs/System/app-specification.md` or `docs/SYSTEM.md` — whichever
      already documents platform secrets — as dev-only.
- [x] Add the regression entry to `TESTS.md`.

## Acceptance Criteria

- **test_bypass_off_by_default:** `TOTPAuthProvider(db, key_loader)` with no `dev_bypass`
  argument, `validate(uid, {"code": "000000"})` against a stubbed db holding a real secret
  whose current code is not `000000` → `False`
- **test_bypass_accepts_any_six_digit_code:** provider built with `dev_bypass=lambda: True`,
  `validate(uid, {"code": "000000"})` → `True`, and `db.query_one` is never called
- **test_bypass_still_requires_six_digits:** `dev_bypass=lambda: True`,
  `validate(uid, {"code": "12345"})` → `False`; `validate(uid, {"code": ""})` → `False`
- **test_bypass_defeats_replay:** `dev_bypass=lambda: True`, call
  `validate(uid, {"code": "000000"})` twice → `True` both times (no `last_totp_window`
  write, so obstacle 2 is gone)
- **test_bypass_logs_warning:** `dev_bypass=lambda: True`, `validate(uid, {"code": "000000"})`
  → a WARNING record on `latarnia.auth.totp` containing the user id
- **test_enabled_in_dev_with_secret:** `ENV=dev` and `LATARNIA_DEV_TOTP_BYPASS=1` →
  `_dev_totp_bypass_enabled()` → `True`
- **test_not_enabled_in_dev_without_secret:** `ENV=dev`, secret absent →
  `_dev_totp_bypass_enabled()` → `False`
- **test_not_enabled_in_tst_with_secret:** `ENV=tst` and `LATARNIA_DEV_TOTP_BYPASS=1` →
  `_dev_totp_bypass_enabled()` → `False`
- **test_not_enabled_in_prd_with_secret:** `ENV=prd` and `LATARNIA_DEV_TOTP_BYPASS=1` →
  `_dev_totp_bypass_enabled()` → `False`
- **test_non_dev_env_does_not_read_secrets_file:** `ENV=prd` with a secret loader that raises
  if called → `_dev_totp_bypass_enabled()` → `False` and the loader was never invoked
- **test_truthy_parsing_accepts:** values `1`, `true`, `TRUE`, `True`, `yes`, `on`,
  `" 1 "` → `is_truthy` → `True`
- **test_truthy_parsing_rejects:** values `0`, `false`, `no`, `off`, `` (empty),
  `"   "`, `None`, `maybe`, `2` → `is_truthy` → `False`
- **test_gate_refuses_every_env_that_get_env_would_coerce_to_dev:** raw ENV of `PRD `,
  ` prd`, `prd `, `Prod`, `production`, `PROD`, `` (empty), unset, `DEV`, ` dev `, or
  `Dev`, each with the secret set → `dev_totp_bypass_enabled()` → `False`
- **test_gate_accepts_only_the_exact_literal_dev:** raw ENV `dev` + secret set → `True`
- **test_config_get_env_really_does_coerce_these_to_dev:** with `ENV="PRD "`,
  `ConfigManager().get_env()` → `"dev"` **and** the gate → `False`; same for
  `production`, `Prod`, and an unset `ENV`. Pins the premise that makes the strict
  raw-ENV comparison necessary.
- **test_login_with_bypass_accepts_wrong_code:** integration — full auth router on a
  throwaway DB with the provider built with `dev_bypass=lambda: True`, an enrolled active
  user, `POST /auth/login` form `username=admin&code=000000` → HTTP 303 to `/dashboard`
  with a `latarnia_session` cookie
- **test_login_without_bypass_rejects_wrong_code:** same fixture, `dev_bypass` absent,
  `POST /auth/login` form `username=admin&code=000000` → HTTP 401 rendering
  `Invalid username or code.`
