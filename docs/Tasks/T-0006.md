## Context

Three integration tests fail on `dev` (and therefore on `tst` and `main`, which
are identical):

```
FAILED tests/integration/test_auth_flow.py::test_hard_delete_removes_user
FAILED tests/integration/test_auth_flow.py::test_reactivate_user
FAILED tests/integration/test_auth_flow.py::test_reissue_setup_token
```

All three are P-0010 tests (cap-006/007/008) and all three fail inside the shared
`_enroll_user` helper with `TypeError` from `pyotp.TOTP(None).now()`.

**Cause — a test bug, not a platform bug.** The TOTP secret is provisioned
lazily: `TOTPAuthProvider.ensure_credentials` runs when the QR setup page is
*rendered*, not when the user is created. `_enroll_user` calls
`POST /api/auth/users` and then immediately reads
`totp.get_existing_secret(user["id"])`, skipping the `GET /auth/setup?token=…`.
No credential row exists yet, so `get_existing_secret` returns `None`
(`totp.py:99-101`) and `pyotp.TOTP(None)` raises.

The two older helpers get this right and are the precedent:
- `_complete_first_setup` — `GET /auth/setup` at `test_auth_flow.py:76`, with the
  comment "GET renders the QR setup page", *before* reading the secret at :80.
- `test_user_management_lifecycle` (cap-024) — `GET /auth/setup?token=…` at :194
  before reading Bob's secret at :197.

`_enroll_user` was added later for P-0010 and omitted the GET.

Discovered while running the pre-promotion regression suite for T-0005. Not
caused by T-0005 (that commit touches only `.github/workflows/` and docs), but it
blocks the "regression suite must be green before `dev → tst`" gate, so it is
fixed on its own branch rather than inside T-0005.

**Not a production defect.** The real browser flow always renders the setup page
before the user can submit a code, so the lazy provisioning is never skipped in
practice. This is why the bug survived the P-0010 merge to `tst` and `prd`.

## Scope

Add the missing `GET /auth/setup?token=…` to `_enroll_user`. Test-only change; no
`src/` change.

Promotion triggers re-checked: single file, test-only, no data-model change, no
new external service — stays a Task.
