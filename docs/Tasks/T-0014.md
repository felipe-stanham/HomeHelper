# T-0014: Secret Manager leaves stale per-app secret files, keeping undeclared Secrets injected

**Status:** [ ]
**Branch:** _not created_
**Created:** 2026-09-08
**Filed by:** T-0013 (diagnosed during T-0012)

## Context

Found while diagnosing an unrelated tst failure during T-0012 and recorded there as out of
scope. Security-relevant: it is the inverse of the P-0006 refuse-to-start gate.

The Secret Manager writes a filtered per-App file at
`/opt/latarnia/{env}/secrets/{app_id}.env` containing only the Secrets the App's Manifest
declares under `requires_secrets`, and systemd injects it with `EnvironmentFile=-`. But
`materialize()` in [`src/latarnia/managers/secret_manager.py:191`](../../src/latarnia/managers/secret_manager.py) early-returns
when the declared list is empty:

```python
declared = list(app_entry.manifest.config.requires_secrets or [])
if not declared:
    return result, None
```

Nothing removes or empties a file written by an earlier version of the Manifest. So when an
App stops declaring a Secret — or stops declaring any — the old file survives on the host and
**keeps injecting values the App no longer declares**. The same hole exists for a partial
narrowing: the write path uses `O_TRUNC` and rewrites only `declared`, so shrinking the list
is handled correctly; it is specifically the drop-to-empty case that leaks, plus any file
belonging to an App that has since been deleted entirely.

### Observed on both hosts

`latarnik`'s Manifest (v0.2.0) declares no `requires_secrets`, yet:

| Host | `secrets/latarnik.env` held | Manifest declares |
|---|---|---|
| tst | `ANTHROPIC_API_KEY` (stale — from a Manifest version that did declare it) | nothing |
| prd | `NOUS_API_KEY`, `ZAI_API_KEY` (hand-written by the operator) | nothing |

This also masked a second, opposite bug: `latarnik/main.py:27` hard-requires
`NOUS_API_KEY`/`ZAI_API_KEY` and exits non-zero without them. Because its Manifest declares
none, the Secret Manager had no reason to inject them — tst crash-looped every 7 s while prd
survived only because its stale file happened to hold the two correct keys. T-0012 applied a
stopgap on tst (appended the two keys to the per-app file, previous version kept as
`latarnik.env.bak-t0012`).

**Not in this task:** the missing `requires_secrets` in latarnik's Manifest. That fix belongs
in latarnik's own repo. This task is the platform-side gap only.

## Scope (proposed — confirm before implementing)

Make the per-app file a true derived view of the Manifest, so it cannot outlive the
declaration that created it. Candidate approach:

- In `materialize()`, when `declared` is empty, unlink any existing
  `{app_id}.env` instead of early-returning.
- Reap orphans: on discovery, remove `secrets/*.env` whose `app_id` no longer resolves to a
  discovered App. P-0009 already established orphan detection on discovery — reuse that hook
  rather than adding a second sweep.
- Decide the operator-override question first: prd's `latarnik.env` was **hand-written**, so a
  naive reaper would delete a file someone is relying on. Either treat any hand-maintained
  per-app file as unsupported (and fix the Manifest instead — the durable answer), or make the
  reaper log-and-skip files it did not write. This is the one open design question.

Open question on rollout: the tst stopgap and prd's hand-written file both need cleaning up on
the hosts once the Manifest is fixed upstream, and that is operator work, not code.

Promotion triggers to re-check when picked up: this looks like a single-component change
(`secret_manager.py` + discovery hook) with no schema change and no new external service, so
it should stay a Task — but confirm against the four triggers before starting.

## Acceptance Criteria (draft)

- **ac-01:** App declares `["A_KEY"]`, file written, Manifest changed to declare nothing,
  discovery re-run → `secrets/{app}.env` no longer exists.
- **ac-02:** App folder deleted → its `secrets/{app}.env` is removed on the next discovery.
- **ac-03:** Narrowing `["A_KEY","B_KEY"]` → `["A_KEY"]` leaves a file containing exactly
  `A_KEY` (regression guard on today's correct behaviour).
- **ac-04:** No Secret value appears in any log line emitted by the new code paths.
- **ac-05:** Directory stays `0700` and any file written stays `0600`.
