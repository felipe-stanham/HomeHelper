# T-0012: Stop backing up app runtime data on deploy; keep 2 snapshots

**Created:** 2026-08-20 | **Status:** [DONE] | **Branch:** `task-T-0012-trim-deploy-backups`

## Problem

`/opt/latarnia` on the homeserver (Pi 5) had grown to **8.2 GB** of a 29 GB card (74% full).
Measured breakdown:

| Path | Size |
|---|---|
| `backups/tst` | 5.8 G (5 snapshots) |
| `backups/prd` | 414 M (3 snapshots) |
| `tst` (live) | 1.5 G |
| `prd` (live) | 505 M |

So **75% of the tree was backups**, and the backups were almost entirely app runtime data.

The `Backup deploy folder` step in both deploy workflows did:

```
rsync -a --exclude='.git' /opt/latarnia/{env}/ "$BACKUP_DIR/$TIMESTAMP/"
ls -1t "$BACKUP_DIR" | tail -n +6 | xargs -I {} rm -rf "$BACKUP_DIR/{}"
```

`.git` was the only exclusion, so each snapshot copied the whole env root — including
`data/` (697 M on tst: 750 PDFs scraped by the `latarnik` App), `apps/` (408 M) and the
platform's own `.venv/` (403 M). That is ~1.5 GB per snapshot × 5 retained. `rsync -a` with
no `--link-dest` means no hardlink dedup: five literal copies of the same PDFs and the same
site-packages tree.

`.venv` was missed on the first pass because `du -sh /opt/latarnia/tst/*` does not expand
dotfiles — the live `tst` root measured 1.1 GB by that glob but was actually 1.5 GB. It only
surfaced when the first executed rsync test produced a 511 MB copy instead of the predicted
<10 MB.

**Why excluding them is safe.** The snapshot's only job is to recover host-local
*gitignored* files that `git reset --hard origin/{ref}` (the next step) would otherwise
destroy — the failure mode recorded in `MEMORY.md` as `deploy-needs-host-config-json`, where
`config/config.json` was recovered from exactly this backup. But `data/` and `apps/` are
gitignored too, and `git reset --hard` does not touch gitignored or untracked paths, so
copying them buys **no** rollback safety. They were pure ballast. The files the snapshot
genuinely protects — `config/config.json`, `secrets.env`, `secrets/`, `caddy/`, `logs/` —
total well under 1 MB.

Retention of 5 was also more than the step is used for: rollback in practice means the
previous deploy, not the one from five deploys ago.

## Decision

1. Anchor-exclude the env root's own `data/`, `apps/` and `.venv/` from the backup rsync.
   Anchored (`/data/`, `/apps/`, `/.venv/`) so only the top-level directories are skipped,
   not a nested directory that happens to share the name. `.venv` qualifies on the same
   grounds as the other two: gitignored, untouched by `git reset --hard`, and fully
   reproducible from `requirements.txt`.
2. Drop retention from 5 to 2 (`tail -n +6` → `tail -n +3`): the snapshot just taken plus
   the previous deploy's.
3. Apply to every environment. `deploy-tst.yml` covers tst on the Pi; `deploy-prd.yml`
   covers **both** prd hosts (Pi and `hetzner-latarnia-1`) because they deploy from one
   `main` push through the T-0005 matrix — so two files cover all three deploy targets.
4. Delete all existing snapshots on the Pi (user-authorized, 2026-08-20).

Also added `-r` to the rotation `xargs` so an empty candidate list cannot invoke `rm -rf`
with an unsubstituted `{}`.

Post-cleanup health confirmed on both Pi envs: tst (`:8000`) and prd (`:8080`) each return
`{"health":"good"}` with Redis and Postgres connected.

The rotation line was re-executed on `hetzner-latarnia-1` (Debian 13) as well, since
`deploy-prd.yml` runs there through the same matrix: 5 seeded snapshots → 2 remained, and
the empty case exited 0 without creating a literal `{}` path. So `xargs -r` and the anchored
excludes are confirmed on both prd hosts, not just the Pi.

**Hetzner snapshot deliberately kept.** That host held one snapshot (136 MB) on a disk at
12% with 32 GB free — no pressure, and it is the only rollback point for the client-facing
prd instance. Deleting it would have bought nothing and cost a recovery point, so the
snapshot purge was applied to the Pi only.

Per-snapshot cost goes from ~1.5 GB to ~5 MB — a ~300× reduction — so the two retained
snapshots now cost ~10 MB total instead of the 5.8 GB the five used to.
